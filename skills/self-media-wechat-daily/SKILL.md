# 公众号每日工作流

## 目标

每天运行一次选题与质量验收，最多生产一篇有独立信息增量的主稿；没有合格选题时明确 `NO_PUBLISH`。让搜索流量沉淀为收藏、分享、常读和有效咨询，同时在发布前拦截同质化、搬运、低信息量和非真人自动化创作。

## 启动

1. 读取账号定位、近 7 天标题与摘要、最近复盘和未完成任务。
2. 读取 [平台低创作度规则](references/platform-quality-rules-2026-07-29.md)、[研究增量与拒绝清单](references/research-increments-2026-07-29.md) 和 [内部验收线](references/internal-gates-2026-07-29.md)。
3. 复制 [每日任务卡](assets/wechat-daily-task-template.md) 建立当天任务。
4. 默认交付发布包。只有终稿确认和草稿箱写入授权同时存在时，才调用 `self-media-wechat-publisher`。

## 每日流程

### 1. 扫描信号

按顺序读取：

1. 与账号定位直接相关的一手官方信息。
2. 后台搜索词、读者问题、评论和历史数据。
3. 用户真实经历、案例和可验证观察。
4. 近 7 天已发内容及其标题、结构、封面和核心结论。

记录信号类型和来源。读者问题型信号需记录真实问题原文或准确搜索词、出现频次和读者阶段；官方更新型信号记录一手发布来源、适用对象和变化。没有可定位信号来源的题标记 `WAIT`；时效稿没有一手来源时停止。

### 2. 通过选题门

每个候选题必须同时回答：

- 谁会搜索或转发它？
- 读者此刻面临什么明确问题？
- 这个问题由什么触发，不解决会造成什么现实损失？
- 与近 7 天同题内容相比，新增了什么事实、判断、案例或行动？
- 同类内容已经讲到哪里，本稿增加了什么认知落差？
- 看完后能完成什么决策或操作？
- 标题承诺能否被正文和证据兑现？

同一事件默认只发一篇主稿。出现新的事实、适用对象或行动变化时才做后续稿。不要把一份官方公告拆成多篇近似提醒。

为候选题标记内容角色：

- `DISCOVERY`：解决明确搜索问题，获得新读者。
- `TRUST`：用数据、案例和方法建立可信度与常读价值。
- `CONVERSION`：回答服务决策问题，引导一个合规、可追踪的下一步。

角色只用于组合实验，不套用外部固定比例。连续 4 周用本账号数据校准配比。

优先级：

- `P0`：短期失效的官方更新，完成核验后生产。
- `P1`：高频搜索问题、关键决策冲突。
- `P2`：可长期搜索和收藏的方法、对照表、案例。

### 3. 建立信息增量包

写正文前必须写清：

- 一句话核心判断。
- 至少两个具体信息增量。
- 一项作者原创贡献：核验、计算、对照、案例、经验或独立分析。
- 一项读者可执行动作。
- 事实、判断、推断和建议的边界。
- 与近 7 天内容的实质差异。
- 本稿唯一母稿 ID，以及是否来自已有内容原子。

只有改写措辞、替换标题、调换段落、换封面，不算信息增量。

### 4. 建立证据包

优先使用主管部门原文、原始数据、用户自有材料和一手采访。记录：

- 来源名称与链接或本地材料。
- 核验时间。
- 关键日期、数字、条件和适用对象。
- 无法确认或会变化的内容。

大段引用外部内容不能替代作者判断。必要引用保持最小充分，并明确来源。

涉及平台算法、推荐、最佳时段或阈值时，标记证据等级：`official`、`backstage`、`own-data`、`third-party-hypothesis`。第三方案例只能作为实验假设，不能写成平台定律。

第一人称经历和“真实客户案例”必须有自有记录或明确授权。合成案例必须标注，禁止虚构身份、经历和用户证言。

### 5. 选择内容结构

- 时效解释：发生了什么 → 谁受影响 → 状态判断 → 现在怎么做。
- 决策指南：冲突 → 判断框架 → 对照案例 → 行动清单。
- 搜索常青：准确问题 → 直接答案 → 条件差异 → 常见误区 → 操作步骤。
- 人物或经历：具体场景 → 决策冲突 → 证据与转折 → 可迁移方法。
- 真问题拆解：QST 真问题 → CON/OPI 概念或判断 → CAS 证据或案例 → SOL 行动。

结构按问题选择。连续两篇采用同一结构时记录理由，不要套用近期文章的相同标题骨架、段落顺序和封面布局。

### 6. 生成并筛选标题

先写三个差异明显的标题：

1. 明确实体或对象 + 具体问题 + 结果。
2. 关键状态 + 常见误判 + 下一步。
3. 决策冲突 + 判断标准。

标题服务搜索和准确点击，不用模糊指代、强迫阅读、空悬念或未兑现情绪。必须与最近 7 天标题做同题检查。

### 7. 写正文

前两段完成：

1. 直接回答标题问题。
2. 说明适用对象和当前结论。
3. 告诉读者本文新增了什么。

正文每一节至少承担一种价值：新事实、新解释、新判断、新案例或新动作。时效内容使用绝对日期，不只写“今天、明天、刚刚”。

结尾只设置一个动作：执行清单、查看菜单、关键词回复、预约或继续阅读。不要用“建议收藏转发”代替值得收藏转发的内容，也不要让每篇文章都导向成交。

### 8. 设计视觉

- 封面与标题共同表达同一主体。
- 优先使用自有图、官方材料、合法图库、流程图、时间线和数据图。
- 正文配图必须解释差异、步骤、时间或证据。
- AI 图片需检查事实合理性、文字错误和视觉误导，并记录生成方式。
- 不复用近期同题文章的同一封面结构。

使用一套主视觉和有限功能组件：标题、引用、Q&A、时间线、对照表、行动清单、延伸阅读。组件必须承担解释功能。写入草稿后在移动端检查溢出、错位、字号、留白和图片清晰度。

### 9. 低创作度预检

逐项拦截：

- 标题、正文或封面与近期内容高度相似。
- 截图搬运、机械拼接、洗稿或大段复述。
- 没有具体信息增量、证据、判断或行动。
- 直接使用 AI 原稿，缺少核验和个人原创贡献。
- 批量生成低成本、低信息量内容。
- 虚构第一人称、客户经历或账号身份。
- 把第三方成功案例、红利数字和算法猜测写成平台事实。

运行：

```bash
python3 scripts/check_wechat_package.py --stage preflight <草稿.md>
```

脚本只验证可确定的结构与状态。语义重复、事实准确和原创贡献仍需人工复核。

### 10. 发布预检与草稿交付

发布前确认：

- 来源、日期、对象和数字已核验。
- 标题、封面、首屏和正文一致。
- 信息增量和原创贡献具体可指出。
- 与近 7 天内容不存在实质重复。
- 引用、图片版权和 AI 辅助状态明确。
- 校验脚本通过。

记录人工选题判断、主要人工修改和事实核验状态，保留来源快照与修改记录。通过后等待终稿确认；人工终审完成后填写审批人和审批时间，再运行：

```bash
python3 scripts/check_wechat_package.py --stage final <草稿.md>
```

用户授权写入草稿箱后调用 `self-media-wechat-publisher`；只允许单篇草稿写入并停在人审，不得形成无人值守的“生成 → 排版 → 连续发布”闭环。

### 11. 选择发布节奏

- 每天运行工作流，默认最多一篇主稿；选题门不通过时 `NO_PUBLISH`。
- 当天发布后出现独立 P0 官方新事实时，允许第二篇，但必须重新建任务、单独验收和单独授权。
- `P0` 在完成核验后尽快进入草稿，不为固定时刻牺牲时效。
- `P1/P2` 使用排期实验，不能把其他平台的 7:30 直接照搬。
- 没有小时级数据时，不宣称某个发布时间最优。

### 12. 资产入库

每篇母稿使用唯一 `source_asset_id`。把可复用内容拆为 QST 问题、CON 概念、OPI 判断、CAS 案例和 SOL 方法，记录来源、首次使用、更新时间与衍生去向。使用 [内容资产账本](assets/wechat-content-asset-ledger-template.md)。

跨平台衍生必须回链母稿，不得新增未经证据包核验的事实。复用问题和证据，重新设计平台标题、开头、结构和行动，不复制粘贴正文。

### 13. 记录与复盘

使用 [单篇复盘卡](assets/wechat-content-review-template.md) 记录：

- 24 小时：阅读、搜索来源、公众号消息来源、分享、收藏、新增关注。
- 7 天：长尾搜索、净增关注、取关、二次传播、常读或完读数据和平台提示。
- 30 天：同类选题中位数、内容角色、信息增量类型、菜单或关键词动作、有效咨询、预约、成交、收入与更新必要性。

后台没有的指标写“不可得”，不能填 0。区分流量、读者质量和业务结果，不用阅读量代替转化。

日终只做一种决策：

- `SCALE`：复用问题结构，不复制正文。
- `DEEPEN`：补证据、案例或决策层。
- `REPACKAGE`：保留正文，重做标题、摘要或封面。
- `STOP`：停止重复母题或低价值结构。
- `WAIT`：数据不足，继续观察。

## 周期复盘

### 每 7 天

比较同类型内容的中位数，回答：

- 哪些准确问题能获得搜索流量？
- 哪些信息增量带来收藏或分享？
- 哪类内容能把阅读转成关注？
- 哪类内容能产生常读、菜单动作或有效咨询？
- 哪些稿件只是同题变体？

只保留一个下一轮实验。

### 每 30 天

更新主线、副线、搜索资产、内容角色配比、禁用母题、低创作度风险模式和内部基线。将重复出现的搜索词或咨询问题转成 FAQ、对照表或咨询清单；只有出现持续需求证据时才进入产品化候选。不要因单篇高阅读忽略平台质量提示，也不要因单篇低阅读直接否定长期搜索资产。

## 完成标准

只有同时满足以下条件才标记 `DONE`：

1. 每日任务卡完整。
2. 已记录真实问题来源、读者阶段、内容角色和母稿 ID。
3. 草稿、封面和正文配图真实存在且可打开，或选题门失败并记录 `NO_PUBLISH`。
4. 至少两个信息增量和一项原创贡献已写明。
5. 近 7 天同题检查已完成。
6. 人工决策、核验、修改、终审和案例来源可追溯。
7. 校验脚本通过。
8. 终稿确认、草稿授权和实际发布状态没有混淆。
9. 已建立 24 小时、7 天和 30 天复盘入口。

存在未核实事实、重复内容、搬运风险、低信息量或直接 AI 原稿时，标记 `BLOCKED`。
